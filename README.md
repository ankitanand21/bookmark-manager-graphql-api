# Bookmark Manager GraphQL API

A small Bookmark Manager backend built for the Burdenoff Product Engineering Intern take-home assignment.

The API uses Bun, TypeScript, GraphQL Yoga, PostgreSQL, Prisma, and Zod. The implementation intentionally stays small and focused on the requested requirements.

## Features

- Create folders
- Create, update, delete, and move bookmarks
- Store bookmark tags as `string[]`
- Fetch a folder with its nested bookmarks
- Search bookmarks by title substring, case-insensitively
- Filter bookmarks by folder
- Cursor-based bookmark pagination
- Input validation with meaningful GraphQL error codes
- Prisma migrations
- Unit tests for resolver behavior
- Integration test against real PostgreSQL
- Docker Compose PostgreSQL setup
- Optional CI workflow

## Tech Stack

- Bun
- TypeScript with strict mode
- GraphQL Yoga
- GraphQL schema-first using `src/graphql/schema.graphql`
- PostgreSQL 16
- Prisma 6
- Zod
- Bun Test

## Setup

### Prerequisites

Install:

- Bun 1.2+
- Docker Desktop or Docker Engine with Compose

### 1. Clone the repository

```bash
git clone <your-github-repository-url>
cd bookmark-manager
```

### 2. Create environment variables

```bash
cp .env.example .env
```

The default `.env` works with the Docker Compose PostgreSQL service.

### 3. Start PostgreSQL

```bash
docker compose up -d
```

### 4. Install dependencies

```bash
bun install
```

### 5. Generate Prisma Client

```bash
bun run gendb
```

### 6. Apply migrations

For a fresh clone, the simplest setup is:

```bash
bun run migrate:deploy
```

For development when changing `prisma/schema.prisma`, use:

```bash
bun run migrate -- --name describe-your-change
```

The migration files in `prisma/migrations` are generated by Prisma Migrate and committed to Git.

### 7. Start the API

```bash
bun run dev
```

GraphQL endpoint:

`http://localhost:4000/graphql`

GraphiQL is available from the same endpoint in a browser during development.

## Database

There are two models:

- `Folder`: stores the folder name and creation time.
- `Bookmark`: stores title, URL, tags, folder ID, and creation time.

A bookmark belongs to exactly one folder. Deleting a folder cascades to its bookmarks.

Indexes are included for `Folder.name`, `Bookmark.folderId`, `Bookmark.title`, and `Bookmark.createdAt` because these fields are used by filtering, searching, relationships, and pagination.

Prisma Migrate is used to generate and apply migrations. Migration SQL should not be manually created as a replacement for Prisma migration tooling.

## API

### Queries

#### List folders

```graphql
query {
  folders {
    id
    name
    createdAt
  }
}
```

#### Get a folder with bookmarks

```graphql
query {
  folder(id: "folder-id") {
    id
    name
    createdAt
    bookmarks {
      id
      title
      url
      tags
    }
  }
}
```

#### Search/filter/paginate bookmarks

```graphql
query {
  bookmarks(
    folderId: "folder-id"
    search: "typescript"
    take: 2
  ) {
    nodes {
      id
      title
      url
      tags
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}
```

For the next page, pass the returned `endCursor` as `cursor`:

```graphql
query {
  bookmarks(take: 2, cursor: "returned-cursor") {
    nodes {
      id
      title
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}
```

### Mutations

```graphql
mutation {
  createFolder(input: { name: "Development" }) {
    id
    name
  }
}
```

```graphql
mutation {
  createBookmark(
    input: {
      title: "TypeScript Handbook"
      url: "https://www.typescriptlang.org/docs/"
      tags: ["typescript", "docs"]
      folderId: "folder-id"
    }
  ) {
    id
    title
    url
    tags
  }
}
```

```graphql
mutation {
  updateBookmark(
    id: "bookmark-id"
    input: {
      title: "Updated title"
      tags: ["typescript", "backend"]
    }
  ) {
    id
    title
    tags
  }
}
```

```graphql
mutation {
  moveBookmark(id: "bookmark-id", folderId: "another-folder-id") {
    id
    folderId
  }
}
```

```graphql
mutation {
  deleteBookmark(id: "bookmark-id")
}
```

## Validation and Errors

The API rejects empty or whitespace-only bookmark titles and malformed URLs.

Validation errors use the GraphQL error extension code `BAD_USER_INPUT`.

Missing bookmarks and folders use `NOT_FOUND`.

An invalid pagination cursor also returns `BAD_USER_INPUT` instead of causing an unhandled server error.

## Pagination Design

Bookmarks are ordered by `createdAt ASC` and then `id ASC` to provide a stable ordering.

The cursor is a base64url-encoded JSON value containing the last returned bookmark's `createdAt` and `id`.

For the next request, the server returns records after that `(createdAt, id)` pair. The API fetches `take + 1` rows so it can determine `hasNextPage` without returning an extra record.

The maximum `take` value is 50 to avoid accidentally requesting an unnecessarily large page.

## How I'd Extend This

If this became a larger production system, I would first add authentication and authorization so bookmark data is associated with users. I would then consider stronger search support such as PostgreSQL full-text search, depending on requirements.

For a growing service, I would add structured logging, request metrics, tracing, and error monitoring. Caching could be introduced after measuring real read patterns rather than adding it prematurely.

If traffic grew significantly, I would consider database connection management, read replicas, query optimization, and horizontal API scaling. API versioning would also be considered if the public GraphQL contract needed breaking changes.

These features are intentionally not implemented because they are outside the scope of this take-home assignment.

## Scope Decisions

The assignment does not require authentication, users, RBAC, caching, Redis, GraphQL Federation, or deployment infrastructure. They are intentionally excluded so the implementation remains focused, understandable, and appropriate for a small internship take-home assignment.
